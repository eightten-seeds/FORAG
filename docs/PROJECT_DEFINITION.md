# 户外功能服装智能养护 RAG 问答系统——项目定义

## 1. 项目名称

基于 LangGraph 与混合检索的户外功能服装智能养护问答系统

## 2. 项目背景

户外功能服装涉及防水透湿面料、防泼水整理、羽绒及合成保温材料等多种技术，其清洗、烘干、防泼水恢复和储存方式存在明显差异。

相关养护知识通常分散在不同品牌官网、Product Care、FAQ 和护理指南中，用户需要在多份专业文档中自行查找。同时，用户通常使用“冲锋衣不挂水了”“羽绒洗完一坨一坨”等口语描述，而官方资料更多使用 DWR、wetting-out、water repellency、loft 等专业术语，导致传统关键词搜索容易出现匹配不足。

因此，本项目关注的核心问题不是“有没有护理资料”，而是：

**如何将用户的自然语言养护问题准确匹配到不同品牌、材料和功能技术对应的官方护理证据，并基于这些证据生成可追溯回答。**

## 3. 项目目标

构建一个可在浏览器中使用的户外功能服装智能养护 RAG Web 系统。

用户输入自然语言养护问题后，系统从官方护理知识库中检索相关证据，对候选内容进行融合与重排序，并基于检索证据生成回答，同时展示答案来源和相关文档片段。

系统重点解决两类问题：

1. 官方护理知识分散，人工查找成本较高。
2. 用户口语表达与官方专业术语存在语义差异，单纯关键词检索容易漏召回。

## 4. 最终系统形态

最终交付为一个浏览器可访问的 Web 智能问答系统。

整体形态：

用户
↓
Vue3 + Vite Web 前端
↓
FastAPI 后端
↓
LangGraph RAG 工作流
↓
BM25 + Dense Vector 混合检索
↓
RRF 融合
↓
Cross-Encoder 重排序
↓
官方护理知识库
↓
Qwen API 基于证据生成
↓
回答 + 来源 + 相关证据

用户无需直接操作 Elasticsearch、模型或命令行，只需要在 Web 页面输入问题即可获得回答。

## 5. 系统输入

输入为用户的自然语言养护问题。

例如：

- “GORE-TEX 冲锋衣应该怎么洗？”
- “为什么我的冲锋衣现在不挂水珠了？”
- “羽绒服洗完以后里面结成一团怎么办？”
- “这件功能服可以放进烘干机吗？”
- “防泼水效果下降是不是代表衣服漏水了？”

输入中可能包含品牌、服装类别、功能技术、材料、异常现象和历史操作等信息。

## 6. 系统输出

系统主要输出：

- 基于检索证据生成的养护回答；
- 对应的官方资料来源；
- 支撑回答的相关知识 Chunk；
- 当证据不足时进行查询重写、重新检索或提示信息不足。

因此，系统不是单纯输出一段大模型文本，而是：

**问题 → 检索证据 → 基于证据回答 → 来源溯源。**

## 7. 核心技术路线

知识库侧：

官方护理资料
→ 文档清洗
→ 结构感知递归切分
→ Metadata 增强
→ Embedding
→ Elasticsearch 索引

在线问答侧：

User Query
→ Query Analysis（一次 Qwen 调用同时输出 structured_query 与 lexical_terms_en）
→ BM25 + Dense Vector 双路召回
→ RRF 排名融合
→ Cross-Encoder 重排序
→ Evidence Grade
→ 证据充分：Qwen API Answer Generation
→ 证据不足：Query Rewrite（最多 1 次）→ 重新检索

LangGraph 负责上述状态、节点、条件分支和查询重写回路的编排。

## 8. 核心业务范围

本项目主要覆盖：

- 户外功能服装清洗；
- 烘干与干燥；
- DWR / 防泼水性能恢复；
- wetting-out 等表面湿润现象；
- GORE-TEX 等功能材料基础护理；
- 羽绒清洗后结团、蓬松度恢复；
- 合成保温服装护理；
- Softshell、Fleece 等服装基础护理；
- 储存和基础维护；
- 基于官方资料的简单性能问题排查。

## 9. 系统边界

本项目不解决：

- 穿搭推荐；
- 商品推荐；
- 尺码推荐；
- 商品价格预测；
- 医疗和皮肤问题；
- 对服装进行专业物理损伤鉴定；
- 自动判断产品是否存在质量问题；
- 替代品牌售后或专业维修机构。

对于“漏水”“破损”等问题，系统只能基于官方资料提供养护和排查信息，不将结果描述为专业故障诊断。

## 10. 项目核心模块

项目最终划分为三个业务模块：

### 模块一：知识库构建

完成官方护理文档从原始数据到 Elasticsearch 可检索知识的转换。

### 模块二：RAG 检索与智能体

完成 Query Analysis、BM25、Dense Vector、RRF、Cross-Encoder、Evidence Grade、Query Rewrite 和 Answer Generation。

这是项目的核心技术模块。

### 模块三：系统应用与量化评测

通过 FastAPI + Vue3 构建 Web 应用，并使用 Recall@5 和 RAGChecker 对系统进行量化评测。

## 11. 本项目重点工作

项目技术重点不是简单调用大语言模型，而是构建完整的 RAG 检索链路：

BM25
+
Dense Vector
↓
RRF
↓
Cross-Encoder
↓
LangGraph 检索闭环

重点解决专业术语精确匹配与用户口语语义匹配并存的问题，并在证据不足时通过 Query Rewrite 重新组织检索。

## 12. 项目最终验收定义

项目完成至少需要满足：

1. 官方护理文档能够被处理并真实写入 Elasticsearch；
2. BM25 与 Dense Vector 能分别完成真实检索；
3. RRF 能真实融合两路排名；
4. Cross-Encoder 能真实对候选文档打分并重新排序；
5. LangGraph 能运行正常检索和 Query Rewrite 分支；
6. FastAPI 能提供完整 RAG 问答接口；
7. Vue 页面能够通过浏览器完成实际问答；
8. 回答能够展示相应来源和证据；
9. Recall@5 能通过 Golden Dataset 真实计算；
10. RAGChecker 能输出真实评测指标；
11. 所有最终量化结果均来自实际运行，不使用 Mock 或写死数据。
